## 已修复及实现

1. 悬浮窗：移除错误的本包 R 引用，按实际应用包查找自有资源；统一真实布局 ID；支持暂停、保存、循环分类、拖动、折叠、隐藏和返回应用。持久回调使用 keepCallback，WebView 销毁时清理；退出移除 View 与 Handler。
2. 后台：Android TimerStore 为唯一权威状态，SharedPreferences 同步持久化。elapsedRealtime + boot count 避免同一次开机期间修改系统时间影响时长；跨进程恢复不依赖 JS 每秒运行。保存日志与重置状态同一次提交，WebView 落盘成功后才确认日志，按稳定 ID 去重。
3. 前台服务：仅用户打开可见悬浮窗时启动；改用 specialUse，并声明具体用途。没有 dataSync 保活、精确闹钟、电池优化豁免或 WakeLock。specialUse 上架仍需要应用商店审核。
4. 统计：整数毫秒活动片段，暂停不计入，切换分类分段，跨自然日拆分；所有图表、分类条、明细、复盘使用 core.js。日按小时、周/月按日期、年按月份显示完整范围。筛选无选择时为 0；隐藏分类的历史记录仍计入“全部”。重叠活动分别累计，合计可能超过自然经过时间，不擅自去重真实重叠活动。
5. 旧记录：没有活动片段的旧记录保持原 duration/date，不用“结束减时长”重造开始。历史错记若没有原始暂停数据无法准确回算。
6. 颜色：持久化按分类名称映射，首页边框及选中态、筛选、趋势、饼图、明细和分类条调用同一个函数；主题和排序不重新分配颜色。没有引入分类 ID，没有更改历史类别名称；旧界面没有独立的两个顶部类别统计卡片。
7. 本地复盘：原复盘中心新增生成/刷新、日期范围、历史；自动内容在 autoReviewsV2，与 review_day/week/month/year 的手写笔记、评分和标签分开。规则只使用总时长、分类合计和占比、连续活动、每日目标及前 7 日平均；没有任务计划数据时不输出任务计划完成率。每天默认22:00在可执行时尝试，下次打开补生成；同周期更新同一键。未接入任何模型或推理服务。
8. 提醒：总开关、类别自选活动类型、各类型间隔和开关、跨午夜免打扰、声音、系统通知、恢复默认值。默认50/20/45/60分钟，类别默认不提醒，避免从名称推断屏幕活动。暂停期间不增加提醒时长；保存、重置、换类重置。前台轻卡片；Android系统通知用非精确 AlarmManager，支持稍后和关闭本次。系统不保证准时，重启/强制停止后需重新打开恢复调度。
9. 数据：完整 JSON 导出 localStorage 与 MascotDB 图片；Android SAF 文件选择器写入/读取，不依赖 WebView 下载支持。导入校验版本、记录/活动片段、任务、复盘、设置和图片；合并去重并保留现有设置，重映射图片 ID，先保存恢复快照；失败回滚 localStorage。提供导入前数据合并恢复。不会把导入的运行中计时覆盖本机计时；建议先保存当前计时再备份。
10. 补录：支持结束为次日，保存失败不修改内存记录，重复提交相同区间不重复添加。旧吉祥物迁移在数据库提交、元数据持久化都成功后才移除旧数组。
11. 性能与界面：1秒显示更新，后台不重绘；每日目标统计缓存；历史复盘按日分组并合并落盘，避免每秒遍历和写入整份历史；设置可滚动、不透明，固定关闭区域；修复重复绑定与重复加载 cordova.js。

## 尚未真机确认及限制

- 没有连接用户手机、旧版真实存储副本或 crash/ANR/logcat，因此不能确认原后台退出究竟是崩溃、系统回收还是冻结，也不能声称已解决全部机型的闪退。
- 锁屏、厂家省电、Android 版本差异、后台通知授权/延迟、SAF 文件保存、悬浮窗拖动和耗电需要手机验收。Robolectric 与 Chrome 不是 Android 真机。
- 开机后单调时钟可靠；如果关机期间又修改系统时钟，无法推知真实离线时长，需核查恢复计时。没有承诺系统永不回收应用。
- 真实旧数据原位升级尚未验证。旧数据结构的模拟兼容通过；测试独立包无法自动读取旧应用私有数据。新备份功能也不能替旧 APK 自动导出其私有数据。
- 正式签名私钥未提供，不能生成可保证覆盖旧版的正式 APK。禁止卸载旧版“解决”签名问题。测试 CI 的 debug 密钥可能每次变化，测试版之间也不能保证直接覆盖；需要稳定测试签名时应另配置专用长期测试密钥。
- Cordova 13 / SDK34 保持现有技术栈用于测试交付；并非当前应用商店上架合规验收。构建工具链 npm audit 有遗留开发依赖告警，未盲目执行破坏性升级；应用核心未新增网络依赖。
- 未新增兑换码、支付或服务器。将来独立授权模块可在应用入口接入，记录/统计/备份模块无需改存储结构；“一次性兑换”必须有可信服务端，完全离线无法跨设备防止重复兑换。导出和恢复能力应始终保留。

## 手机最短验收

1. 保留旧版，安装名称为“拾光橘 V2 测试”、包名 com.shiguangju.test 的最终 APK。不要卸载旧版，不要先导入正式数据。
2. 开始1分钟，暂停半分钟再恢复1分钟，保存；记录应约2分钟而非2分半，重复点保存不增加记录。
3. 开启悬浮窗并授权，切换其他应用/锁屏，再返回；测试暂停、换类、保存、折叠、关闭。检查记录总和与图表一致。
4. 用测试数据补录跨午夜记录，检查两天、跨月/年统计；切换深浅色确认类别一致。
5. 复盘页写笔记和评分，再生成/刷新自动复盘，确认笔记保留。设置提醒类型与1分钟间隔、免打扰和通知开关，确认暂停、稍后和关闭行为。
6. 上传一张测试吉祥物，导出JSON并确认文件存在，再连续导入两次，确认记录、笔记、图片均不重复。完成以上验证后再安排旧版数据迁移方案。
